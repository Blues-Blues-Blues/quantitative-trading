```python
def finalize(self, trade_log, signals, equity_curve, *, kline=None):

```

具体接线：

1. `main.py::run_pipeline` 在同一次 `engine.run()` 之后，调用 `writer.finalize(..., kline=ds.kline)`。
2. 起止日期、初始现金和来源信息复用 writer 的 manifest；主流程目前从空仓开始。报告股票集合按本次明确请求的 `ds.meta['symbols']`（存在且为代码列表时）顺序，与 `ds.symbols()` 做稳定并集，传入 writer；不能只用实际行情代码，否则请求过但完全缺行情的股票没有区块。行情额外包含但本次未回测的市场参考证券不能混入；成交或持仓中出现集合外股票按输入矛盾报错。
3. `snapshot` 每次用当前 positions **覆盖**当日日末候选；即使当前为空表，也必须覆盖上一次有仓候选。先冲刷旧日，再保存新日候选和时间，不能将新日第一笔快照写到旧日。
4. `_flush_day` 在清空逐 Bar 缓冲之前，固化最后一个快照时间、总权益及完整持仓状态；可直接复用已有 `_positions[-1]`，不必每个 Bar 再深拷贝一次。只累积日频结果，最后一天在 finalize 中冲刷，同一天不得重复追加。
5. 空仓日也保留“确实收到该时点完整快照”的记录及总权益。仅对该完整快照中未持有的回测股票补股数、市值、仓位为零。缺少整日快照或最后快照早于账户日末时必须报错，不能补成空仓，也不能从历史最后一条有仓记录前向填充。
6. writer 提供给构建函数的 `positions_daily` 是密集表，字段固定为 `ts, symbol, shares, mark_price, market_value, total_equity`；每个账户交易日×每个报告股票恰好一行，`ts` 必须等于账户当天最后一个 Bar 时间。空仓标记价允许缺失，总权益必须为该时点真实值。构建函数接到缺行的密集表应拒绝，而不是再次静默补零。
7. HTML 内的数据由 `build_visualization_data` 一次生成，数值计算集中在 Python，JS 只负责展示和筛选。
8. 原调用 `finalize(log, signals, curve)` 未传行情时仍生成原分析产物；manifest 的 HTML 状态写 `skipped`，原因是未提供行情。主回测入口必须传行情，不能走此兼容降级路径。
9. 现有 `--no-analysis-report` 同时关闭 HTML 和分析 writer；更新帮助文字。主流程无需新增第二个报告开关。旧 `_plot_smoke_charts` 保留现有行为，不把它当作 HTML 替代品。
10. 优化器目前直接构建引擎，不要把报告导出挂到 `BacktestEngine.run()`。普通引擎调用、优化 trial、导入模块均不得自动创建报告目录或加载 Plotly。
11. `finalize` 保留原 `quality` 字典返回值，不能改成 HTML 路径。成功路径从 `writer.path / 'backtest.html'` 取得；`visualization` 状态写 manifest，不覆盖原 quality 字段。原三参数调用也不要求新的初始资金、股票列表或日末密集表校验；这些新增校验仅在请求生成 HTML 时执行。

### 3.4 生命周期与错误处理

- 在原有 manifest 中新增独立 `visualization` 字段，例如 `schema_version, status, html_file, warnings, error`；`html_file` 使用 `backtest.html` 相对文件名。
- 可视化状态使用 `pending / complete / partial / skipped / failed`；原归因状态的含义保持一致。
- `manifest.status` 在无异常时继续使用原归因 quality 状态；HTML 有可展示缺失时只将 `visualization.status` 标为 partial，日志须同时打印两个状态，不能笼统宣称整份报告完全正常。出现致命异常仍按原 fail 规则将顶层 status 标 failed。
- 只有数据整理、HTML 写入全部完成才能标记 `complete`。归因 `no_closed_trades` 不妨碍 HTML `complete`。
- HTML 先写同目录临时文件，再替换最终文件；失败不得留下被宣称有效的残缺 HTML。
- 写入失败或输入严重矛盾时，记录 HTML 失败，沿用 writer 的 `fail()` 行为并抛出异常。保留已经落盘的分析产物，不重新运行回测。
- 个别股票缺行情等可展示的缺失使用 `partial` 加页面说明。成本/仓位不一致、重复成交 ID、超卖等不能悄悄画成正常结果。
- 如果扩充 `code_content_hashes`，加入新增 Python、模板和 JS 文件；避免读取不存在的文件导致兼容调用失败。
- 顺序必须为：冲刷最后一天 → 现有分析产物 → 构建/写入 HTML 或明确 skipped → 写最终 manifest → 设置 `_finished=True` → 返回原 quality。不要在新增 HTML 工作开始前保留旧位置的 `_finished=True` 或输出最终成功日志。
- `kline=None` 才表示兼容调用不请求 HTML；显式传入空行情表仍表示请求生成，应生成有说明的 partial 报告（账户数据须有效），不能以 `if kline.empty` 自动跳过。
- 警告应有稳定 `code`、可选 `symbol/date` 和中文 message，按原因/股票汇总，避免数百条重复提示。普通无成交、未平仓、均线预热不足属于正常状态，不自动标 partial；缺行情、缺共同基准、已知行情字段不完整属于 partial。

## 4. 数据口径：实现时必须遵守

### 4.1 日线与时间

- 唯一行情来源为本次引擎使用的 `ds.kline`。不重新获取数据、不另行复权、不调用策略特征流水线。
- 时间统一为上海本地时间：带时区先转 `Asia/Shanghai`，再按当地日期分组；无时区按项目现有上海本地时间约定处理。
- 以规范化后账户曲线的 `t0=min(ts)`、`t1=max(ts)` 为实际回测边界，行情先裁到 `[t0,t1]` 再聚合，不能只按日期截取而混入首尾日区间之外的 Bar。元数据日期与实际范围不一致时，页面显示实际范围并说明差异。
- 浏览器横轴使用 `YYYY-MM-DD` 日期字符串，成交显示当地 `YYYY-MM-DD HH:mm:ss`，不让浏览器时区改变成交日期。
- 按 `symbol`、时间排序后逐日聚合：open=第一根有效开盘，high=最高，low=最低，close=最后有效收盘，volume=当日成交量总和。全缺失成交量不能通过 sum 默认值变成真实零量。
- 不制造周末、节假日 K 线，不用前值补成假 K 线；股票停牌或没有行情时保留价格数据缺口。
- 统一日轴为账户 Bar 所在上海日期的去重升序列表。每股 `daily` 以及对比序列重索引到该日轴；无行情日的 OHLC、volume、均线及股票收益值为 null，持仓字段仍来自当天账户快照。只省略日期并设置 `connectgaps=false` 不足以断线，必须实际插入 null 占位。null 行不是 K 线，不增加交易日或成交量。
- 对 OHLC 全缺失的日期不画 K 线；部分缺失标记质量问题，折线可以使用有效 close；非正价格或重复 `(symbol, timestamp)` 要显式校验，不能重复累加成交量。
- 成交量单位复用输入约定；当前真实行情说明为股。信息不足时标“原始单位”，不擅自除以 100 当作手。
- 均线用有效日收盘价滚动计算，窗口 5/20/60，`min_periods=window`；不足时留空，不填零、不前向偷取未来值。默认不额外下载预热段。
- 均线先在该股有有效 close 的交易日上计算，再映射到统一日轴；缺行情日均线显示 null，不把停牌日当作新增样本。
- 页面仅展示本次实际回测范围，不能把预热段展示成策略已运行区间。
- 页面标注“价格口径与本次回测输入一致”；复权标识未知时标未知，不能声称已复权。
- 由分钟输入聚合得到的 OHLC 只覆盖实际提供的时段。首尾不足完整交易日或已知中途缺 Bar 时，显示“按可用 Bar 聚合”，附实际首末时刻；不要宣称经过完整行情校验。无需新增交易日历或完整性侦测系统，没有证据时也不要将未知缺口解释成停牌。

### 4.2 真实成交与四类动作

- 只取 `shares > 0`。拒单、T+1 等待、取消和最后一根 Bar 未成交信号均不展示为成交。
- 使用 `trade_log.ts` 和 `trade_log.price`；不得使用信号决策时间、日收盘价或滑点前开盘价替代实际成交。
- 按 `ts, event_seq` 稳定排序；先按该顺序重建持仓，再分类：
  - 买方向成交前股数为 0：买入。
  - 买方向成交前股数大于 0：加仓。
  - 卖方向成交后股数大于 0：减仓。
  - 卖方向成交后股数为 0：清仓。
- 当前实际买方向为 `BUY/ADD`，实际卖方向为 `SELL`。不要仅根据原始 action 文案判断是否清仓，T+1 顺延的部分卖出也按真实剩余股数分类。
- 对同一时间戳多笔成交，必须保留 `event_seq` 顺序。
- 保留 `fill_id` 作为明细和图表关联键；重复 ID 拒绝。兼容旧日志时，先对**完整 trade_log（含拒单）**统一调用现有 `_prepare_trade_log`，再筛选展示成交；将相同规范化结果传给 `closed_trades`。旧 ID 由行位置产生，若先删拒单再单独生成 ID，会与原日志 PnL 的 ID 不一致。可增加薄的公共包装函数，不能复制另一套规范化算法。
- 原日志没有 `event_seq` 时沿用规范化后的稳定行序，在报告内生成展示顺序；不向输入日志回写。日志已有 event_seq 则必须验证唯一整数，不能因表格排序重编。
- 当前主流程初始空仓。若调用者提供了包含未知期初持仓的截断日志，必须拒绝重建并说明原因；本次不开发历史持仓导入功能。

### 4.3 同日汇总标记与实际价格

- 按 `(symbol, date, action_type)` 汇总，每天最多四种动作标记，使用形状和中文文字共同区分，不能只靠颜色。
- 单笔组的 y 值就是实际成交价。多笔组的 y 值为 `sum(price * shares) / sum(shares)`，必须写“汇总成交均价”，不能让用户误以为是一笔真实成交。
- 悬停显示：日期、动作、笔数、合计股数、汇总成交均价、最低/最高实际成交价；卖方向额外显示已实现盈亏合计。
- 点击任一汇总标记，展开该股票该日的**全部**实际成交，按事件顺序显示，并高亮对应动作组。
- 不通过偏移价格或日期来避让重叠。完全重叠时点击任何可见标记仍应进入当天全量明细，其他动作不能不可访问。
- 点击一笔明细后，在当天日期、该笔实际价格处显示独立选中标记，并展示实际成交时间；切换线图/K 线不丢失选中项。
- 滑点可能使实际成交价格落在原行情高低点之外；不裁剪价格、改写高低价或丢弃成交。纵轴范围须包含可见的真实成交及成本线。

### 4.4 成本线、股数与仓位

成本线口径必须与 `Account` 一致，**不含交易手续费**：

```text
买入后成本 = (买入前股数 × 买入前成本 + 本次股数 × 实际成交价) / 买入后股数
部分卖出后成本 = 卖出前成本
清仓后成本 = null
重新开仓 = 新一轮持仓成本
```

- 在报告层按有序实际成交重建成本和成交前后股数；不调用账户买卖方法、不修改真实账户。
- 每日取截至该账户日末快照时刻的成本状态，画阶梯线；无仓日期留空并禁止跨空仓区间连线。
- 日内清仓后重新买入以当日最后持仓状态绘制成本线，日内变化可以在逐笔明细的成交后成本中查看。
- 日末持仓股数、市值和权益来源为现有 snapshot，股数必须与成交重建结果一致；不一致立即报错。
- 仓位 = `market_value / total_equity`，显示为百分比。非正或非有限总权益属于致命输入错误，与现有 ExposureAnalyzer 一致；不得为了绘图将异常分母改成 1 或静默补零。
- 股票当天无行情但仍持仓时，继续使用账户快照已有标记市值；不要用图表缺失价格将其市值置零。页面可提示该日没有新行情。
- 图表分别显示股数和仓位，单位必须明确，可使用同一持仓副图的双纵轴。
- 不以累计买入额充当持仓市值，不用回测最终持仓反填过去历史。

### 4.5 卖出已实现盈亏

- 复用 `analytics.metrics.closed_trades(trade_log)`，按 `sell_fill_id` 唯一关联实际 SELL 明细。
- 该口径包含买入费用分摊及卖出费用，与成本线的账户持仓成本口径不同。页面简短说明“成本线不含手续费；已实现盈亏含交易费用”。
- 不依据 `reason` 过滤合法卖出；减仓、清仓、顺延卖出均可产生已实现盈亏。
- 每笔卖出只能计入一次；不得把归因批次的多行当成多笔卖出重复统计。
- 校验实际 SELL 的 fill_id 集合与 `closed_trades` 返回的 sell_fill_id 集合完全相等且一一对应；缺少盈亏、重复盈亏或多出未知成交的盈亏均报错，不能只比较汇总金额。
- 买入/加仓的已实现盈亏显示“—”，不能显示 0 来暗示盈亏已结算。
- 汇总盈亏必须与现有 `closed_trades` 和 `evaluate` 的 `total_pnl` 一致；它不等于包含未实现损益的账户总收益。
- 金额计算保留原精度，展示时再格式化；价格至少显示四位小数，明细悬停可显示原始精度。
- 明细 fees 固定为 `commission + stamp_duty + transfer_fee`，amount 为原日志毛成交额。成交价已经包含滑点，不把 `slippage_bps` 再作为费用扣一次；不是另行按展示价格重算佣金。实际正股数成交须有有限正 price、整数 shares 及合法方向，amount 与 `price * shares` 在数值容差内一致。

### 4.6 账户与涨跌幅对比

账户概览：

- 初始资金、期末权益、累计收益率 `期末权益 / initial_cash - 1`、实际成交笔数、卖出笔数、已实现盈亏、最大回撤。
- 期末权益、累计收益均基于整个账户，不能由个股已实现盈亏相加替代。
- 最大回撤复用 `evaluate`，保留其现有全 Bar 口径，不修改原指标定义。
- 净值折线取每天最后一根账户 Bar 的 `total_equity / initial_cash`。
- 回撤先在完整账户 Bar 序列按现有累计峰值计算 `equity / cummax(equity) - 1`，再取每日最小值绘制，标为“当日最深回撤”。这样日线展示不会漏掉日内最大回撤；图中最大绝对值须与现有最大回撤指标一致。
- 日期缩放不重算摘要、不重置回撤峰值；页面注明摘要为完整回测区间。

涨跌幅对比图采用固定的区间起点：

- 定义 t0 为本次账户曲线第一根 Bar 的准确时刻，D0 为其上海日期。每只股票必须使用**同一 t0 Bar 的有效 open**作为区间价格基准：`日收盘价 / open_at_t0 - 1`；不能拿一只股票 09:31、另一只 10:00 的首笔行情冒充同一比较起点。
- 策略用 `日末权益 / initial_cash - 1`，图例标“策略账户收益率”。
- 起点基准为 t0 Bar 开始前的初始资金与该 Bar 的开盘价；t0 可能是日内时刻，页面显示准确基准时间，不笼统称为当日开盘。首日日末收益可以不为 0，不能为了视觉从零出发抹掉首日收益或费用。
- 某股 t0 没有有效 open 时，即使 D0 稍晚有行情，也不加入可比序列，并显示“缺少共同起点价格”。它的个股价格图仍正常显示可用数据。
- 缺行情日期保留 null，关闭跨缺口连线；缩放、筛选时基准不变。
- 图例和说明明确“股票价格涨跌幅（不计交易成本及现金分红）”与“策略账户收益率（含现金仓位及交易成本）”，不把两者当作相同收益来源。
- 不增加指数下载。来源若未处理除权除息，应原样说明输入口径，不在可视化模块自行调整价格。

### 4.7 序列化数据结构

`report_data` 至少包含以下字段，定义一个独立的可视化 schema 版本：

```text
schema_version
meta: run_id, start, end, start_ts, end_ts, timezone, initial_cash, symbols,
      price_basis, aggregation_note
summary: initial_cash, final_equity, total_return, fill_count, sell_count,
         realized_pnl, max_drawdown
account_daily[]: date, total_equity, nav, return_pct, worst_drawdown
comparison: base_date, base_ts, stock_base_prices, series, excluded_symbols
stocks[]:
  symbol, display_name(可选), status
  daily[]: date, open, high, low, close, volume, ma5, ma20, ma60,
           shares, mark_price, market_value, position_weight, cost_basis,
           first_bar_ts, last_bar_ts
  markers[]: date, action_type, fill_ids, count, shares, weighted_price,
             min_price, max_price, realized_pnl
fills[]: fill_id, event_seq, symbol, date, ts, side, action_type, price,
         shares, amount, fees, realized_pnl, shares_before, shares_after,
         cost_basis_after
warnings[]: code, symbol(可选), date(可选), message
```

- JS 内数据的百分比字段统一使用比例值（例如 0.12），格式化为 12%；名称和代码注释必须说明，禁止 Python/JS 双重乘 100。
- 标的代码使用字符串，不丢失前导零，不通过截断代码合并不同证券。
- 所有 NaN/Inf/NaT 转为 null，JSON 禁止非标准数值；不能把缺失价格、指标替换为 0。
- 表格显示文字使用安全转义或 `textContent`；嵌入 JSON 处理 `</script>`、`<` 等字符，不能让股票名称或元数据破坏 HTML。
- 不将原始完整配置、文件绝对路径或分钟日志无差别塞入页面；只内嵌本次展示需要的数据。

### 4.8 输入契约与一致性校验

- `initial_cash` 必须显式提供且有限、为正；不能从第一日末权益反推。`symbols` 非空、无重复、均为非空字符串。
- `equity_curve` 必须非空，至少有 `ts, total_equity, position_value`；ts 非空且唯一，规范化后排序。净值必须有限且为正。重复账户时间直接报错，避免不同函数各自取一行。
- 股票存在但零成交是正常情况；无账户曲线则无法生成有效回测报告，应明确失败，不能生成全零成功页面。单个账户 Bar 则允许生成，净值、回撤、成本等单点使用 marker 保证可见。
- `trade_log` 空表允许，输出带固定 schema 的空明细；不能对空的规范化结果无条件访问可能不存在的 price 列。非空日志按现有 normalization 的必需列校验，不缺省补费用为零。
- 所有实际成交的 ts 必须在账户时间轴中，成交所属证券必须在报告集合中；截断、超范围或未知证券不能静默删掉。
- 日末密集持仓表 `(date,symbol)` 必须唯一完整，ts 与账户当天最后时刻完全一致；同日各行 total_equity 与账户值一致。
- 股数非负整数；有仓 mark_price 有限正数，`market_value ≈ shares * mark_price`；空仓 market_value 必须为 0，成本为 null。
- 各股日末市值合计必须等于该时点 `equity_curve.position_value`；每股股数必须等于截止该 ts 的成交累计净股数。不能用“总量刚好相同”掩盖股票间串行关联。
- 股数及标识精确比较；金额和权益用 `atol=1e-6, rtol=1e-10` 的浮点容差，展示舍入不参与校验。前述确定样例维持 1e-6 绝对误差要求。
- 行情非正价格、OHLC 内部矛盾（例如 high < low）、重复键为错误；部分字段缺失可为 partial。未知行情代码或超范围 Bar 不加入报告；若其对应真实成交或持仓，则不能静默忽略，应按上述关联规则检查。

这些校验应由数据构建层完成，不能等浏览器显示后才暴露为 NaN、空图或 JS 异常。

## 5. 页面与交互规范

### 5.1 页面顺序

```text
回测报告标题、区间、股票数、运行标识、数据说明
账户摘要卡片
日期起止输入 / 恢复全区间 / 日期联动开关
账户净值图
账户当日最深回撤图
股票涨跌幅 + 策略账户收益率对比图
股票定位目录
股票 A：标题及摘要、K线/折线切换、均线和成本线开关
        价格与成交图
        成交量
        持仓股数与仓位
股票 B：同上
其余股票：同上
全部真实成交明细表、筛选、分页、选中成交详情
指标与价格口径说明、必要的数据缺失提示
```

- 所有股票默认在同一页面展开，不能改成下拉框一次仅能看一只或每只单独一个 HTML。
- 每行一个完整股票区块，横轴日期范围相同、价格纵轴各自独立。
- 中文标题与单位清晰，价格单位元、股数单位股、收益和仓位为百分比；系统中文字体即可，无需在线字体。
- 默认 K 线，涨红跌绿；成交类型使用独立形状/文字，避免与 K 线涨跌颜色混淆。
- 价格、成交量、持仓副图共享日期范围；不把价格、成交量和股数压在同一纵轴。
- 初始显示整个回测区间。切换 K 线/折线只切价格 trace，均线、成本、标记和缩放状态保留。
- 无成交时展示“本次回测无成交”，价格和零持仓仍显示；未清仓显示期末持仓，不补一笔假卖出。
- 没有行情的股票保留区块说明，不能悄悄从股票列表消失。

### 5.2 日期联动

- 默认开启，同步净值、回撤、对比、所有个股及其副图的时间范围。
- 支持框选缩放、拖动、日期起止输入、恢复全区间；恢复操作应同步。
- 关闭时，不同股票与账户图独立缩放，但同一股票的三个副图保持联动。
- 顶部手动输入日期范围及“恢复全区间”属于显式全局操作，即使联动关闭也作用于所有图；在按钮附近说明此行为。
- 联动范围内无数据的股票显示空窗口，不跳到其他日期；重新开启联动的范围按下一条状态规则确定。
- 维护明确的页面状态：`globalRange`、`lastInteractedRange`、每股票 `localRange`、`selectedFillId`、图形模式和表格筛选。联动关闭时顶部标明“未联动”，单图拖动只更新该图 localRange 和 lastInteractedRange；重新开启时采用 lastInteractedRange（尚未操作则用 globalRange）统一，避免不清楚“最近范围”指哪一张图。
- 顶部日期输入使用包含首尾日期的范围；起日大于末日时提示并保持旧范围，超出回测区间则裁剪。单日范围保留当天数据并给予合理横轴边距，不能零宽导致空图。
- 使用实际日期轴，不使用每股各自的第 N 根 K 线序号。首版允许日历空隙，不能因各股停牌日期不同导致同一横坐标代表不同日期。
- 若统一隐藏周末等休市日，必须所有图使用同一日历规则；不要分别按每股缺失日期折叠横轴。
- `plotly_relayout` 同步必须有防重入及相同范围跳过机制，等待异步更新完成再解除锁，避免图之间无限互相触发。
- 只同步 x 轴；不将价格 y 轴同步给其他股票或百分比图。
- 懒加载图使用同一状态仓库；尚未创建的股票被目录/明细定位时先初始化，再应用范围与选中标记。处理完成后回收程序化更新锁；异步失败不能把整个页面永久锁住。

### 5.3 明细与定位

- 表格默认时间升序，字段：股票、实际成交时间、动作、成交价、股数、成交额、费用、卖出已实现盈亏、成交后股数。
- 提供股票、动作、日期范围筛选及“清除筛选”；每页默认 50 条。筛选不能改变账户摘要的统计区间。
- 日汇总标记点击后，表格定位该股票该日，列出所有真实成交；界面显示当前筛选条件，提供恢复全部入口。
- 点击日汇总时清除旧动作筛选并重置到第一页，避免“当天全部成交”仍被旧筛选隐藏；当天超过 50 笔时允许分页，但当天全部成交均须可访问。
- 点击任意成交行：滚动至相应股票、选中成交日期及实际价格，显示成交详情。
- 若选中日期不在当前可见范围，默认定位为该日前后各 10 个账户交易日，边界裁剪到回测区间；若已可见则保留范围。
- 联动开启时该定位范围同步其他图；关闭时仅更新对应股票区块。
- 表格行和图标关联依赖 `fill_id`，不能以当前页行号、舍入后的价格或只有日期的键关联。
- 图表缩放不自动过滤交易表；表格日期筛选独立控制，避免联动时成交被悄悄隐藏。表格筛选改变若排除当前选中成交则清除 selectedFillId 与选中标记；普通翻页或价格图模式切换不改变所选成交。
- 不显示 reason、signal_id、策略评分和因子解释；必要内部 ID 可保留在数据中供关联，不在主要用户流程展示。

## 6. 技术方案与资源限制

采用 Plotly Python 生成图形数据，原生 HTML/CSS/JavaScript 组织页面：

- Plotly 官方支持导出自包含交互 HTML；绘图库资源可内嵌，从而离线打开。[官方 HTML 导出文档](https://plotly.com/python/interactive-html-export/)
- 点击成交和日期同步使用 `plotly_click`、`plotly_relayout` 等事件。[官方事件文档](https://plotly.com/javascript/plotlyjs-events/)

实施要求：

1. 在 requirements 中声明兼容的 Plotly 版本范围，使用实际安装版本完成验收并在交付说明中记录；不凭记忆指定未经验证的最低版本。
2. 整份 HTML 只内嵌一份 Plotly.js；各个图不能重复打包一份库。禁用 CDN、远程字体、在线资源和云端上传入口。
3. 输出中内嵌日线、日末账户/持仓和真实成交；不能内嵌全量分钟行情、所有信号或拒单日志。
4. 首版以 2～4 股约 500 个交易日流畅查看为目标；结构不能硬编码四只股票。用最多 20 股约 500 日的合成日频数据检查扩展性，不跑真实回测。
5. 股票增多可通过 IntersectionObserver 延迟初始化图形；仍在同一页面保留全部区块，滚动到时出现，且继承当前全局日期范围。不要把懒加载做成只能打开一只。
6. 表格分页，成交数据索引预建，避免每次悬停全量扫描所有成交；事件绑定一次，切换模式不重复绑定。
7. 日末持仓收集随天数×股票数增长；不重复读入全部分钟 Parquet。保留原 writer 按日冲刷的内存特性。
8. 两年多股验收只构造日频展示数据；另用现有几根 Bar 的引擎 fixture 校验真实接口接线。
9. 模块导入无输出副作用，模板从 `__file__` 附近定位，Windows 中文和空格路径可用。
10. 新增函数说明输入/输出、单位、时区、费用口径和异常；JS 注释重点解释同步锁、成交 ID 与状态保持，便于维护。
11. 首版明确支持桌面版 Edge/Chrome 的本地文件打开，至少记录其中一个浏览器的实际验收版本；页面缩放或窗口改变后图表自适应。按钮、日期输入和成交行有可见焦点及基本键盘操作，无需新增移动端专用功能。
12. 在新增测试中对优化入口设置失败哨兵（例如 `Study.optimize` 被调用就失败），不能为了“测试报表”执行寻优。测试中模拟输出路径、浏览器打开和网络调用，确保不会生成用户意外打开的窗口或访问真实行情。

## 7. 必须覆盖的验收场景

以下是交给执行 AI 的实施验收要求。本次编写文档未执行任何测试。

### T01 日线聚合与缺失

- 同日两根 Bar：第一根 `(open=10, high=12, low=9, close=11, volume=100)`，第二根 `(11,13,10,12,200)`；日线必须是 `(10,13,9,12,300)`。
- 交错输入的两只股票分别聚合；周末不出现假 K 线；全缺失 volume 不能变成真实 0。
- 测上海日期边界、带时区输入、重复键、OHLC 缺失和 MA 不足窗口。

### T02 实际成交与动作分类

- 一次买入、一次加仓、一次部分卖出、一次清仓，分别分类为四个动作。
- 信号与成交跨天时标记成交日；拒单 shares=0 不产生标记或明细。
- T+1 等待后部分卖出仍属于减仓；后续实际卖完才是清仓。
- 同一时间戳多笔成交按 event_seq 排序；分类、成本和 PnL 不能由不稳定排序决定。

### T03 成本与含费盈亏的确定样例

构造符合时间顺序的真实成交，各次卖出满足 T+1；手续费按给定数值进入日志：

| 顺序 | 操作 | 股数 | 价格 | 金额 | 买/卖费用合计 |
| --- | --- | ---: | ---: | ---: | ---: |
| 1 | 买入 | 1000 | 10 | 10000 | 10 |
| 2 | 加仓 | 500 | 14 | 7000 | 5 |
| 3 | 减仓 | 600 | 15 | 9000 | 9 |
| 4 | 清仓 | 900 | 12 | 10800 | 10 |

- 前两笔账户成本线分别为 10、`17000/1500 = 11.333333...`。
- 减仓后 900 股，账户成本仍为 `11.333333...`。
- 盈亏计算使用含买费总成本 17015；第一笔卖出 PnL 为 `9000 - 9 - 600 * (17015/1500) = 2185`。
- 剩余含费成本 10209，第二笔卖出 PnL 为 `10800 - 10 - 10209 = 581`。
- 总已实现盈亏 2766；清仓后成本 null，不跨空仓区间连线。
- 买费拆入 commission/transfer_fee，买入 stamp_duty=0；不能改变原 metrics 的费用解释。
- 数值比较允许 1e-6 浮点误差，不允许提前将均价截成两位小数后计算。

### T04 同日多笔与表格映射

- 同一天同类成交两笔，均价按股数加权，保留两笔 ID；数量和卖出盈亏按笔合计。
- 同一天既卖出旧仓又买入新仓时，买卖均存在；点击任一组列出当日全部成交。
- 完全重叠的不同动作、价格在日高低范围外、带小数价格，均可通过表格访问真实记录。
- 行点击定位使用真实价格，切换 K 线/折线之后选中状态仍存在。

### T05 持仓快照与空仓

- 同日早先有仓、最后一根 Bar 清仓：日末为 0，不取早先最后一条非空记录。
- 第一日全空仓、第二日持仓、第三日清仓，daily 持仓三天齐全。
- 期末未平仓不生成虚假清仓；无成交股票仍有行情、零持仓。
- 缺行情但有仓时市值使用账户快照；股数重建与快照冲突必须报错。

### T06 账户、回撤和比较基准

- 初始资金 1000，首日权益 990，显示首日账户收益 -1%，不能以首日末 990 重新定为零。
- 某股首日 open=10、close=11，首日价格涨跌幅 10%；后续 close=12 为 20%。
- 首日缺行情的股票在对比图列为不可比，不能偷偷用第二日作为零点。
- 某日 Bar 权益先到 1200、后到 900、末尾回到 1100，当日最深回撤为 -25%；顶部最大回撤为 25%，不能仅看日末漏掉它。
- 放大日期区间不重置归一化基准、摘要和回撤峰值。

### T07 文件与关闭开关

- HTML 文件、内嵌数据和必要图形非空，JSON 不含 NaN/Inf。
- 只内嵌一份 Plotly.js，无外部 script/link 依赖、无 fetch 读取本地相邻文件；库源代码自身包含 URL 字符串不等于页面主动联网，静态检查不要误报。
- 从其他 cwd 调用时默认输出仍在项目根目录；中文空格目录可写、可开；连续两次运行目录不同。
- `--no-analysis-report` 不构造 writer、不生成 HTML、不导入 Plotly；直接构建引擎无自动报告副作用。
- 旧三参数 finalize 调用仍可用，manifest 明确 HTML skipped；main 的新调用须生成 HTML。
- 模拟写文件失败时 manifest 标 failed，不残留有效最终 HTML，不重跑引擎。

### T08 回归与输入不变性

- 使用现有 `tests/test_analysis_reporting.py::small_engine` 或同等小型 fixture，分别关闭/开启报告跑同样输入。
- 新增开启 HTML 的用例必须调用 `finalize(..., kline=engine.data.kline)`；仅重复旧三参数调用只能覆盖 skipped 路径，不能算作 HTML 集成测试。另在 main 层用短 fixture 或依赖替换检查行情实参确实传入。
- 实际 trade_log、equity_curve、已有绩效指标相同；报告数据函数不原地修改输入表。
- 原归因和暴露输出继续存在，既有 `tests/test_analysis_reporting.py` 的短用例继续通过。
- 检查优化器源码调用路径，确保不新增 HTML 导出或目录写入；不为此运行 Optuna。

### T09 浏览器交互验收

只断言 HTML 字符串包含按钮不代表功能通过。使用可用浏览器工具或小型浏览器自动化实际打开合成报告，完成：

1. 4 只股票、约 500 日的合成报告在同页单列呈现；无浏览器 JS 错误。
2. K 线/折线切换、MA 和成本线开关正常。
3. 日期联动开/关、恢复全区间、日期输入、表格点击定位正常，无事件循环卡死。
4. 点击同日汇总可见每笔成交，含时间、实际价格、数量、卖出盈亏。
5. 复制单个 HTML 到另一文件夹，禁用网络后依然可用；页面不发外部资源请求。
6. 用最多 20 股约 500 日的合成展示数据记录生成耗时、HTML 大小和浏览器初次可用情况。记录环境与结果，不承诺未经测量的固定耗时。

如果环境没有可用浏览器执行能力，交付中明确“浏览器交互未验证”并给出手工步骤，不能写成全部验收通过；也不要为了验收自动运行长时间真实回测。

### T10 日期轴、缺失快照与基准时刻

- 账户三个交易日 D1/D2/D3；A 仅 D1/D3 有行情、D2 仍持仓，B 三日都有行情。A.daily 必须三行，D2 OHLC、volume、MA、比较收益为 null，但持仓市值和仓位保持真实快照值；浏览器折线在 D2 断开。
- 账户 D1 最后时刻 15:00，持仓只收到 14:59 快照：失败。完全没有 D2 快照：失败。确实收到 D2 15:00 空表快照：允许，补为该日全部零持仓。
- 跨日第一根 Bar 不得覆盖旧日日末候选；最后一天只追加一次，flush 后继续满足原测试中分钟缓冲已清空的断言。
- t0 为 D1 10:00，A 有 10:00 open=10，B 首笔到 10:01 才出现：A 可以比较，B 排除并说明。首日有行情不等于拥有共同起点。
- 额外行情含 D1 09:59、区间结束后 Bar：不参与图形、MA或涨跌幅；标题显示实际 t0/t1，不宣称完整日行情。
- 请求股票包含无任何行情的 C：保留 C 的说明区块和零持仓，不从报告股票数中删除。

### T11 日志 ID、数值与对账

- 旧日志含“拒单、买入、拒单、卖出”，无 fill_id/event_seq：规范化后明细 SELL 与 closed_trades 的 ID 必须一致；同时已有部分真实 fill_id 时也不冲突。
- 缺一条/重复一条 sell_fill_id 对应 PnL，即便总盈亏凑巧相同仍失败。
- 实际成交价格非正、amount 与 price×shares 矛盾、未知实际方向、超范围成交、非正权益、缺 initial_cash、重复账户时间，分别给出可定位的错误。
- 股数总量相同但 A/B 股数互换、市值合计不等于 position_value，也应失败。
- 空成交表成功输出空明细；有账户且显式空行情表生成 partial；无账户曲线失败；只有一个有效 Bar 时图形单点可见。
- 净值收益、仓位、回撤在 Python/JS 间不重复乘 100；滑点不作为第二项费用扣除。

### T12 交互状态、输出状态与文本嵌入

- 联动关闭后先拖动 A，再拖动 B，重新开启按最后 B 范围同步；顶部全局日期输入和恢复仍作用于全部图。
- 单日范围、起止倒置、完全越界日期均按规格处理；没有数据的窗口不会自动跳日。
- 表格先筛选“买入”，再点卖出日汇总，仍能查看当天全部买卖；超过 50 笔可翻页，页码被正确重置。
- 隐藏价格模式 trace 或懒加载后再定位成交，均保留正确 fill_id；股票切换、图表恢复或异常不触发无限 relayout。
- 名称/元数据含中文、引号、换行、`<`、`&`、`</script>` 时，HTML 可打开且只作为数据文本显示；数据 null 展示“—”，不能渲染成 0 或抛 JS 错误。
- 旧 finalize 的返回值和 quality 状态保持兼容；HTML complete/partial/skipped/failed 与 manifest、日志一致，失败不能被后续成功赋值覆盖。
- HTML 关闭时是否导入 Plotly 应在独立进程或隔离导入状态中检查，避免其他测试已导入 Plotly 导致假失败。
